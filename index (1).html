1. AWS Identity and Access Management

IAM helps control access to AWS services and resources.

Core IAM components

  • Users: Identities for people or applications.
  • Groups: Collections of users with shared permissions.
  • Roles: Identities that provide temporary credentials to trusted entities.
  • Policies: JSON permission documents that define allowed or denied actions.

Security best practices

  • Apply least privilege: grant only the permissions required.
  • Enable multi-factor authentication (MFA).
  • Do not share access keys or private credentials.
  • Review permissions regularly and remove unused access.

2. Amazon EC2

Amazon Elastic Compute Cloud provides resizable virtual servers called instances.

Launch an instance

Select an Amazon Machine Image (AMI), instance type, key pair, network, and storage settings.

Configure a security group

Allow HTTP on port 80 for website traffic. Restrict SSH on port 22 to your trusted IP address.

Install a web server

Install and start Apache HTTP Server, then place the website files in its document root.

4. Deployment Workflow

Typical steps to deploy this page on an Amazon Linux EC2 instance.

Launch EC2
Choose an Amazon Linux AMI and a suitable instance type.
Set network access
Allow HTTP (80); restrict SSH (22) to your own IP address.
Connect securely
Connect using EC2 Instance Connect or SSH with your key pair.
Install Apache
Install and start the Apache web server.
Upload website files
Copy this index.html file to /var/www/html/.
Test the website
Open http://YOUR-EC2-PUBLIC-IP in a browser.
Important: Replace the sample public IP with the actual public IPv4 address of your running EC2 instance. The website is not live until you deploy it to a hosting service.
